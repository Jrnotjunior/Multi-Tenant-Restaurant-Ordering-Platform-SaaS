# Security policy

## Reporting a vulnerability

Please do not publish suspected vulnerabilities, credentials, customer data, or exploit details in a public issue. Use GitHub's **Report a vulnerability** flow for this repository when private vulnerability reporting is available. If that option is unavailable, contact the repository maintainer privately through the contact method listed on the maintainer's GitHub profile and include only the minimum detail needed to reproduce the issue.

Reports should include the affected component and version, impact, reproduction steps, and any suggested mitigation. Do not include real customer records or live credentials. If a credential may have been exposed, identify the credential type and affected system without pasting its value.

## Supported versions

Security fixes are currently made against the `main` branch. There is no separate release-support policy yet.

## Status

This policy is a reporting path, not evidence of a SOC 2 audit or certification. The control owners must establish and document triage, response time, escalation, customer notification, and closure procedures in the incident-response plan.
