# W2T-003 — Privileged identity foundation

## Database (deployed on Web2Table only)
- \`platform_admins\`: explicit, trusted platform admin allowlist. **No users are enrolled automatically.**
- \`privileged_invitations\`: tenant-scoped invitations with constrained role/branch and expiration, email, inviter and recipient identity.
- Server-enforced RPCs: \`request_privileged_invitation\` and \`accept_privileged_invitation\`.
- Sensitive bodies reside in the \`private\` schema. The public RPC wrappers are SECURITY INVOKER and can be called only by authenticated users.
- Platform admins can request owner invitations only after completing MFA.
- Restaurant owners can request staff invitations only for their own active tenant and an active branch.
- Invitation acceptance requires a confirmed email, matching invited Auth user ID, correct invitation state, and MFA AAL2.
- Both invitation request and acceptance are inaccessible to anonymous users.
- Only service-role/trusted provisioning can write the invite status and initial platform admin allowlist.
- Neither account creation nor an invitation URL alone makes someone a member.

## UI (code on GitHub)
- \`/admin\` and \`/restaurant\` require Supabase Auth, authenticator enrollment or verification, then a database membership check.
- A valid invitation ID in \`?invite_id=<uuid>\` can be redeemed only after MFA; the database validates all authorization and identity checks.
- Privileged login is password-based; invite recipients can set a password after following the Auth invitation link. No public privileged signup exists.
- All operational content remains a nonfunctional scaffold until tenant onboarding is implemented.

## Edge Function (source only: NOT deployed yet)
- \`send-privileged-invitation\` uses a caller bearer token, the restricted RPC, and Supabase Auth admin email invitations.
- Must configure \`APP_INVITE_REDIRECT_URL\` to the final HTTPS \`/restaurant\` URL, plus Supabase Auth allowed redirect URLs, before deploying.
- Test an actual invitation email, role enforcement, MFA and expired/replayed links on staging before opening onboarding.
