# W2T-002 — Multi-tenant database foundation

## Scope and deployment
Target Supabase project: **Web2Table**, reference `wvibrchebfwirbgkcnbr`. Do not apply this migration to `Restaurant Ordering Platform` or any other project.

Source: `supabase/migrations/20261024000000_w2t_002_multitenant_foundation.sql`.

## Tables
- `tenants`: restaurant-level identity, lifecycle and public-safe slug
- `branches`: per-tenant operational branch identity (inactive until configured)
- `tenant_memberships`: owner/staff membership bound to Supabase Auth users
- `branch_memberships`: composite foreign keys ensure branch and employee belong to the same tenant
- `tenant_domains`: globally unique canonical hostnames, pending verification, activation timestamps and hashed challenge value

## Access model
No direct anonymous table privileges. Authenticated users have SELECT only; no INSERT, UPDATE or DELETE privileges on the five tables.

PostgreSQL RLS restricts visibility to:
- MFA-verified active members for tenant details and their own membership
- MFA-verified owners for all branches, team membership and domains in their tenant
- MFA-verified staff for branches they have explicitly been assigned

Server-only provisioning will be implemented during W2T-003. There is intentionally no browser privilege to create tenants or elevate staff. A domain marked pending is **not validated**; ownership verification and TLS provisioning remain W2T-004.

The helper functions live in an unexposed `private` schema with fixed `search_path`, explicit `auth.uid()` checks and narrowly granted EXECUTE permissions.

## Review checklist
- Verify five tables exist with RLS enabled and correct constraints
- Verify no anonymous or authenticated table mutation privileges
- Verify owner cannot see another tenant, and staff cannot read another branch
- Verify AAL1 denies operational reads; AAL2 is required
- Verify cross-tenant foreign key inserts are rejected
- Run Supabase security and performance advisors
- Confirm no test customers or restaurant data were persisted

This is a foundational security layer, not a working ordering system. Do not enable live signup, payments or dashboard data access until later tasks are complete.
